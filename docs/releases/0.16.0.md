# TorroMail 0.16.0

Assistants can now write formatted HTML mail. The connection check also covers
the outgoing mail server, so a broken SMTP setting shows up before the first
send. (That check was prepared as 0.15.1, which was never published; it ships
here.)

## Changed

- **HTML drafts:** `mail_create_draft` accepts an optional `html_body`. The
  message then carries a formatted HTML part and a plain-text part
  (`multipart/alternative`, nested in `multipart/mixed` with attachments).
  Both are quoted-printable, so long HTML lines stay valid mail.
- **TorroMail writes the plain text itself:** like a mail program sending HTML,
  it derives the plain-text part from the HTML — tags removed, link targets
  shown as ` <url>`, images as `[image: alt <src>]`. That text is what you see
  when you review and approve the send. `body` and `html_body` cannot be
  combined, and HTML with no readable words (only images, for instance) is
  refused.
- **Plain-text drafts are unchanged:** without `html_body` a draft is composed
  byte for byte as before, so retries and drafts already waiting for approval
  are unaffected.

## Fixed

- **Test Connection checks SMTP as well as IMAP:** after the mailbox login
  succeeds, TorroMail connects to the account's outgoing server (TLS or
  STARTTLS, EHLO, login) and drops the session; nothing is sent. A failure
  says `outgoing server: …` so it is clear which half to fix, and is classified
  like the mailbox's: a refused login, an untrusted certificate or an
  unreachable server.
- **Status dot follows suit:** the startup check and the 15-minute background
  monitor use the same check, so a broken outgoing server now turns the dot red
  by the same rules as a broken mailbox. Accounts without an outgoing server
  are unchanged.

## Known limits

- The derived plain text is an approximation, not a renderer, and the HTML is
  not sanitized: a mail program can show what the text leaves out, for
  example text generated by CSS, form values, the content of an image, or
  markup a browser reads differently. You approve the send as before.
- Embedded `cid:` images (`multipart/related`) are not supported.
- The terminal surface (`torromail`) reports an untrusted certificate as its
  own message but cannot trust it yet; use the app for that decision.
